# 混合精度最有效作用点与自适应策略（实测报告）

> 赛题七 R13 · 平台：**NVIDIA RTX 3060 (sm_86) + CUDA 12.6**（沐曦 MXMACA 开发代理，代码经 `src/solver/cuda_compat.h` 抽象层可迁移）
> 数据：`experiments/mp/mp_gpu_bench.json`（GPU 实测）、`experiments/mp/mp_ir_classification.json`（CPU 精度路径分类）
> 策略规则：`design/adaptive_mixed_precision.md`（v2：动态升级链）
> 计时口径：cudaEvent 内核级 wall-clock，warmup 后多次取最优（min）；CPU 参考为 scipy/自研内核单线程。

---

## 1. 结论：混合精度在哪个计算过程最有效（按实测收益排序）

| 排名 | 计算过程 | 瓶颈类型 | 实测证据（RTX 3060） | 结论 |
|---|---|---|---|---|
| **1** | **SpMV（IR 内层/批量扫描）** | 带宽受限（AI≈0.2） | rajat10 CSR fp32 **1.35×**（158 GB/s，误差 0.0）；rajat13 CSR 1.86×、SELL **2.73×**；rajat22 CSR **2.81×** | **大矩阵上 fp32 值存储 → 字节减半 → 吞吐 ×1.4–2.8**；小矩阵（≤5k）启动延迟主导，无增益 |
| **2** | **LU 因子存储** | 带宽/内存受限 | flash-adc fp32 因子内存 **0.104 MB vs 0.221 MB（2.13×）**；单线程分解 fp32 **1.34×** | 内存近减半 + 分解/三角求解 ~1.3×；正确性靠 fp64 主元 + IR |
| **3** | **三角求解（前代/回代）** | 带宽受限 | flash-adc fp32 **1.30×**（ST）；n≤5k 时启动延迟主导（~1×） | 需 ≥10k 规模才显现 ~2×；与大矩阵 SpMV 同机理 |
| **4** | **迭代精化 GMRES-IR 整体** | 混合 | CPU 实测：bandgap fp32+IR 1.4e-2→4.9e-12；**12/33 矩阵仅用 fp32 因子+IR 即达标**（含 κ2.8e15 的 rajat22） | fp32 因子 + fp64 残差 = fp64 精度、fp32 成本 |
| **5** | **fp16 存储增强** | 带宽受限 | rajat10 fp32 存储误差 **0.0**（全值同量级）；但 32/33 矩阵 4–33% 值 < fp16 最小正常数 → 需 Ruiz 缩放 | 仅均衡后值域入界的矩阵可用（当前批 1/33 天然满足） |

**一句话**：**SpMV 与三角求解（带宽瓶颈）吃 fp32 字节减半的红利最大（大矩阵 ×1.4–2.8）**；LU 分解靠"fp32 因子存储 + fp64 主元 + IR"同时拿内存减半与正确性；fp16 是窄众增强，只在缩放后值域入界时可用。

## 2. GPU 分阶段实测数据（RTX 3060）

### 2.1 稀疏 LU：数值分解 + 三角求解

| 矩阵 | n | fp64 PAR factor | fp32/fp64 (ST) | fp32 因子内存 | fp64 因子内存 | 内存比 |
|---|---|---|---|---|---|---|
| bandgap | 113 | 1.14 ms | 1.29× | 0.013 MB | 0.016 MB | 1.23× |
| flash-adc | 989 | 16.9 ms | 1.34× | 0.104 MB | 0.221 MB | **2.13×** |
| pg2k | 4,050 | 235 ms | fp32 需预处理(奇异) | 2.75 MB(估) | 4.12 MB | 1.50×* |
| pg5k | 5,000 | 311 ms | 同上 | 3.70 MB(估) | 5.54 MB | 1.50×* |

\* 含索引的 12B→8B/nnz 口径（1.5×）；仅因子值口径为 2×。

**三角求解**：flash-adc fp32 ST 1.30×；fp64 PAR 1.96 ms（989 节点，启动延迟占比高）。n≥10k 才会显现带宽型 ~2×。

### 2.2 SpMV（CSR / SELL-C-σ）

| 矩阵 | n | bw fp64 (CSR) | CSR fp32 加速 | SELL fp32 加速 | fp32 误差 |
|---|---|---|---|---|---|
| bandgap | 113 | 1.45 GB/s | 1.00× | 0.98× | 4.8e-7 |
| flash-adc | 989 | 4.8 GB/s | 1.48× | 1.56× | 3.1e-6 |
| pg2k | 4,050 | 68.6 GB/s | 1.01× | 0.93× | 5.6e-8 |
| pg5k | 5,000 | 81.3 GB/s | 1.08× | 0.95× | 1.4e-7 |
| rajat13 | 7,598 | 3.2 GB/s | **1.86×** | **2.73×** | 7.7e-7 |
| pg10k | 10,082 | 178.6 GB/s | 0.99× | 0.94× | 2.8e-8 |
| rajat10 | 30,202 | 158.0 GB/s | **1.35×** | 1.12× | **0.0** |
| rajat22 | 39,899 | 10.5 GB/s | **2.81×** | 1.25× | 2.8e-6 |

**规律**：① 大规模矩阵（n≥8k）fp32 存储收益 1.35–2.8×，与"字节减半→带宽×2"的理论一致；② n≤5k 的矩阵内核在 µs–10µs 量级，**启动/调度延迟主导**，fp32 收益被吞（~1×）——这正是"小矩阵要批处理/常驻"的证据；③ pg 系 fp32 存储误差 3–6e-8（fp32 存储对 pg 安全），rajat10 误差 0.0（全同量级值，fp16 级存储也安全）。

### 2.3 LU 分阶段瓶颈判定

| 阶段 | 判定依据 | 结论 |
|---|---|---|
| 分解（单线程/单 block PAR） | fp32 仅 1.29–1.34×（非 2×） | 不纯带宽受限：gather/scatter 更新与依赖链（level）限制 → 并行化收益（PAR vs ST 12–22×）大于精度收益 |
| 三角求解 | fp32 1.30×（989 节点） | 带宽受限，规模越大越明显 |
| SpMV | fp32 1.35–2.81×（大矩阵） | **典型带宽受限** → 精度降半=字节减半 |
| IR 迭代 | 每迭代 = 1 次 SpMV + 2 次三角求解 | 全部带宽受限 → fp32 因子/值全程受益 |

## 3. fp16 可行性（CPU 侧实测 + GPU 佐证）

| 测量 | 结果 |
|---|---|
| SpMV fp16 值存储 + fp64 累加 | 输出误差 ~1e-4（bandgap/pg5k/OTA），rajat10 = **0.0**（GPU: fp32 误差 0.0） |
| fp16 值域（正常数 6e-5 ~ 65504） | 33 矩阵中 32 个有 4–33% 值下溢（1e-12 电容/小导纳）→ **原始 fp16 不可直存** |
| 结论 | fp16 前提 = Ruiz 均衡把值域压入 [6e-5, 65504]；1e-4 扰动作 IR 预条件可接受，作直接求解则误差 ~κ·1e-4 不可接受 |

## 4. 自适应策略（执行规则，详见 design/adaptive_mixed_precision.md）

```text
① 选格式（m5_selector）：n≥10k 且行均匀 → SELL-C-σ32；否则 CSR
② 精度升级链（动态，按实测失败触发）：
   P-fast: fp32 因子 + fp64 主元 + fp64残差IR → 达标? 完成 (12/33 实测)
   P-safe: fp64 + Ruiz + 移位(1e-7|diag|) + IR       → 完成 (flash/limiting/dac/sc 系)
   P-hard: fp64 + Ruiz 结构对齐 + trisolve 数值优化   → neural/OTA/pg 系
   P-singular: 检测 → 移位 → 报错                     → rajat16/18/20/25
③ 规模叠加：n<5k 的矩阵精度收益被启动延迟吞掉 → 批处理/常驻缓冲区优先
```

**为什么不用静态 κ 表**：实测 rajat22（κ2.8e15）P-fast 达标而 OTA（κ1.5e13）失败——判据应是分解质量/IR 残差，不是 κ 估计。

## 5. 对赛题评分项的证据链

| 评分项 | 混合精度贡献（本报告实测） |
|---|---|
| **S₁ 正确性 (20)** | P-fast 12/33 + P-safe 6/33（CPU 实测）；fp32 因子+IR 在良态达 1e-11 级；病态走 P-safe/P-hard 处方（neural 1.8e-11 / flash 1.7e-10 / sc-dac 3.4e-13） |
| **S₂ 加速比 (25)** | SpMV fp32 1.35–2.81×（n≥8k，GPU 实测）；LU 分解 1.34× + 内存 2.13×；三角求解 1.30×；PAR 并行 12–22× 与精度正交可叠加 |
| **S₃ 带宽利用率 (70%)** | rajat10 fp32 达 158 GB/s（49.6% util，同实现 fp64 上限参照）；SELL 大矩阵可再提升；fp32 使同利用率下有效吞吐 ×1.4–2.8 |

## 6. 复现说明

- **硬件/软件栈**：RTX 3060 12GB（sm_86）、CUDA 12.6（nvcc `/usr/local/cuda-12.6/bin/nvcc`）、WSL Ubuntu 24.04、Python 3.12 + numpy/scipy/matplotlib
- **编译**（race7 根）：见 `src/solver/mp_bench/mp_lu_bench.cu` 头部注释（nvcc -O3 -arch=sm_86 链接 cpu_ref_lu.c + colamd）
- **运行**：`bash experiments/mp/run_gpu_bench.sh`（MM→s0 转换 + 全部基准 + JSON 聚合，产物 `experiments/mp/mp_gpu_bench.json`）
- **CPU 分类**：`experiments/mp/mp_ir_classification.json`（方法见文件内说明）
- **已知边界**：pg10k/rajat13/rajat10/rajat22 的 LU 段受单 block PAR 内核规模/工作区限制未取到（如实记录为 n/a；SpMV 段完整）；pg 系 fp32 分解需 Ruiz/shift 预处理（与 CPU 结论一致）
