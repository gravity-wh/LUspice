## 3. 并行化收益：比混合精度高一个数量级

| 方式 | 分解 21.9 s → | 加速 |
|---|---|---|
| fp32 因子（单线程） | 21.7 s | **1.02×** |
| 单 block 并行（fp64） | **733 ms** | **29.9×** |
| 三角求解并行 | 118 ms → 13.4 ms | **8.8×** |

这是本次实验最硬的结论：**在 X201 上，把单线程内核改成并行，收益是混合精度的 30 倍。**

代码里这两个旋钮本来是正交的，可以叠加；但资源有限时，先做并行——优先级不该有争议。

## 4. 与 RTX 3060 的结论不一致（重点）

| 指标 | RTX 3060（sm_86） | 沐曦 X201 |
|---|---|---|
| 分解加速（fp32 因子，ST） | **1.34×**（flash-adc） | **1.02×**（pg2k，区间 [0.97, 1.04]） |
| 三角求解加速 | 1.30× | 1.01× |
| 因子内存减半 | 2.13× | 1.50×（含索引口径，值口径仍 2×） |
| ST 分解绝对耗时 | 210 ms（n=989） | 21899 ms（n=4050） |

**3060 上的"fp32 因子 ~1.3×"在 X201 上没有复现。**

### 可能的原因（推断，未经 profiler 验证）

1. **X201 的带宽远不成瓶颈**。HBM 峰值 1843 GB/s，是 3060（360 GB/s）的 5 倍。
   混合精度的全部收益建立在"带宽受限"这个前提上；前提不成立，收益自然消失。
2. **21.9 s 的耗时更像延迟受限而非带宽受限**。单线程内核做 gather/scatter 随机访存、
   无指令级并行，时间主要花在**等每一次访存返回**，而不是**搬多少字节**。
   字节减半对"等待次数"没有影响，所以时间几乎不变。
3. 同规模下 X201 的单线程绝对耗时比 3060 高两个数量级，说明该内核在 X201 上
   远未接近访存吞吐上限——这本身就是"延迟受限"的旁证。

### 这对结论意味着什么

> **混合精度的收益是条件性的，条件是"带宽受限"。**
> 在带宽充裕的目标硬件上，这条路不成立；在带宽紧张的开发卡上，它成立（1.3–2.8×）。

所以本仓库 README 里那张 SpMV 加速表（1.35–2.81×）**不能直接搬到 X201 上引用**。
X201 侧只验证了 LU 分解/三角求解两段，SpMV 与 IR 内层尚未在 X201 上测。

## 5. 稳定性与失败模式

按实验脚本自定的判读口径：

| CV | 口径 | 本次 |
|---|---|---|
| ≤ 0.5% | 可写单点数 | — |
| 0.5% ~ 3% | **只能写区间** | **分解 2.05%、三角 1.29% ✓** |
| > 3% | 抖动主导，需报机理 | — |

**因此正确表述是"分解加速落在 [0.97, 1.04]，与 1.0 无法区分"，而不是"1.02×"。**

9 次尝试中 1 次失败（11%）：

```
[19:15:40][HCR][E]ht_signal.cpp:592 : Failed signal [0xa0000fe80] wait
CUDA FAIL mp_lu_bench.cu:352  cudaMemcpy(&sing, d_sing, ...):
          an illegal memory access was encountered
```

报错点在 `read_status` 的 D2H 拷贝（`mp_lu_bench.cu:352`），但这是**延迟报错**——
真正的越界发生在前面的内核里，错误被 CUDA 运行时挂起，直到下一次同步才抛出。
X201 上该内核存在偶发越界（3060 上同样代码未出现），未定位到具体位置。

另有 1 次 `rc=137`（594 s 被 SIGKILL，超过单轮 600 s 上限）。

## 6. 覆盖范围与缺口

| 项 | 状态 |
|---|---|
| LU 数值分解（fp64 / fp32，ST + PAR） | ✅ 8 次有效运行 |
| 三角求解（fp64 / fp32，ST + PAR） | ✅ |
| 因子内存 | ✅ |
| 分解质量（nnz 一致性） | ✅ |
| **SpMV（CSR / SELL）** | ❌ 未在 X201 上测 |
| **GMRES-IR 端到端** | ❌ 未在 X201 上测 |
| 其他矩阵（flash-adc / rajat / pg5k…） | ❌ 只测了 pg2k |
| 带宽计数器（ht-smi / htSml） | ❌ 未采 |

**单矩阵、单规模，不足以支撑"X201 上混合精度整体收益"的结论。**
本文件能支持的结论只有一条：*在 pg2k 这个规模上，X201 的 LU 分解从 fp32 因子里拿不到
可测收益，而并行化能拿到 30×。*
